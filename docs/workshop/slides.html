Welcome back

  • Today one new participant joins that workflow: a coding agent.
  • Subject matter expertise now matters more than programming skill.

Say the opening claim once and move on. The two rules follow on their own slide.

Two room rules

  1. Never make another human read AI slop.

Read everything it does. Every round ends with the same question: would I merge this?

  1. Commit often.

A commit is a checkpoint you can return to and a line in the record. Today: a commit after every run that changed a file, one pull request per sprint.

Minute three. Both rules come back all day: rule one at every “would I merge this?”, rule two at the end of every Your turn.

Spectrum line

Stand along the tape line.

  1. Left end: never used AI for research. Right end: use an agent every week.
  2. Two voices from each end.
  3. Re-sort: how much do you trust the output? Two voices again.

First movement of the day, before any slide with content. The trust re-sort is the one to listen to.

Four questions

  • What must never go in? The agent reads whole folders. Personal and sensitive data never go into a repository, private ones included.
  • How do I know this is right? Most useful on work you could have done yourself, least trustworthy where you cannot check it (Doctorow, 2026).
  • Could I recreate it if the AI were gone? Fine that the AI made it. A problem when it has to stay in the loop for you to change it.
  • What do I say, and to whom? Declare the tool as a method. Do not cite the model as a source.

With your neighbour: which one worries you most, and why?

The arguments are on the four background pages. Two neighbour minutes, no share-out; the questions return in the disclosure block.

How the day works

  • The same path twice: question, agent, commits, pull request, release.
  • Sprint 1, before lunch: three questions of your own, one framed run, then studio cards on your repository with a commit after each, a pull request you merge yourself, release v0.1.0. Fast and rough, on purpose.
  • Sprint 2, after lunch: a plan you edit, issues a colleague reviews, a run that continues from your phone, a reviewed pull request, a CLAUDE.md, release v0.2.0, one declaration over both.
  • Every round ends with the same check: would I merge this?
  • Two snack breaks, each with a question to take with you. The evidence wall collects what you notice. The day closes with a zine.

How the recall works

One sentence describes the whole workflow. It has six blanks. It comes back five times today, each time with more blanks to fill.

  1. The sentence appears with the newest blanks empty.
  2. Twenty seconds: tell your neighbour what goes in.
  3. Reveal.
  4. Write the whole sentence so far on the back of your day sheet.

Filling the blank from memory is what makes it stick. By 17:00 you can say the workflow without the slide, and it goes on the last page of your zine.

Learning objectives

By the end of this workshop, you will be able to:

  1. Run an agent inside the Git workflow: give it a task, have the plan reviewed and written as issues before any code exists, then review the pull request and accept or reject it.
  2. Judge the difference a plan makes: compare one line against a reviewed plan, and say what changed and why.
  3. Judge the difference documentation makes: a plain CSV against a data package, a bare repository against one with a template, a codebook and a CLAUDE.md.
  4. Declare agent use: point to the record your workflow produced, up to a tagged release, and say what it shows.

CLAUDE.md

  • CLAUDE.md in the project folder: versioned, shared with collaborators, in the record.
  • It holds what is true for this project: the template, the naming rules, where the codebook is, how to render.
  • Told the agent something three times? Put it in CLAUDE.md.
  • A user level file (~/.claude/CLAUDE.md) exists on your machine, applies to every project, and never appears in the repository.

The user level file is a hint only, nothing to do.

CLAUDE.md against a skill

  • A skill has two parts: the when is always sent to the model, the what loads on demand.
  • Lots of text for one purpose: make it a skill.
  • Never write skills prospectively. Extract them from a conversation that just happened.

Disclosure rules in the making: two records

Two sides of the room

Disclose if AI was used at all.

A threshold each author judges invites under-reporting. The workflow logs every use anyway.

A yes-or-no flag loses the intent.

It cannot tell translation of your own ideas from ghostwriting, and readers will read it as a quality signal.

Stand on your side. Argue with v0.1.0 and v0.2.0 as evidence. Cross over if persuaded.
