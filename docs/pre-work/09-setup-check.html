Step 9: Test your setup and report done

Due by Friday, 25 September 2026

Twenty minutes. This runs everything from steps 4 to 8 once, in the order the day uses it, on the setup you cloned in step 4, and ends with an assigned to me so I know you are ready. Have Zotero open, and RStudio open with the setup project (File, Open Project, then setup.Rproj in the folder you cloned).

NoteWhy not your own repository

The does not see your data before the day. The rule from step 1 about what goes into a repository applies to what an agent reads, and we set the safety rails together in the room. Your setup repository holds a few hundred rows of public WASH investment data instead, which is enough to test every connection.

1. Both connections

Open a at the setup folder, the way you did in step 4, and place it next to the RStudio window. Run:

claude mcp list

Both r-mcptools and zotero end in Connected. If one does not, go back to step 6 or step 8 before continuing.

2. Put the data in your R session

In the Files pane at the bottom right, click 01-read-data.R to open it, then click Source at the top right of the editor. There is nothing to edit. The Console prints a line starting with “Loaded”, and the Environment pane at the top right lists two objects, investments and investments_by_country.

3. A read-only run in plan mode

In that terminal, start Claude Code:

claude

Press Shift+Tab until the status line at the bottom says plan mode. In the agent reads and proposes. It does not change anything. Ask these three things, one at a time, and wait for each answer:

Read the files in the data folder and describe what is in them. Do not change anything.

What objects are in my R session, and how many rows does the largest one have?

List five items from my Zotero library with their citation keys.

When Claude Code asks before using a tool, read the prompt and allow it. In most of these steps run without asking, and each answer names the tool it used. The three answers show the agent reading the sample data, your , and your own library.

NoteIf it proposes something you did not ask for

Say no. In plan mode the agent may only read. Anything else is a good story for the chat room.

4. A file and a commit

Press Shift+Tab to leave plan mode. Ask:

Create a file called SETUP.md at the top of this repository. In it, list my operating system, the Claude Code version, whether the r-mcptools and zotero servers are connected, and a short summary of what is in the data folder. Do not run git.

The agent shows the file it wants to write. Read it and accept. Then type /exit.

Commit and the file yourself, the way you did in the first workshop: in the RStudio , tick SETUP.md to it, click Commit, write “Add setup report” as the message, click Commit, then Push. Open the repository on GitHub and check that SETUP.md is there.

Today you do every commit yourself. On the day you hand the agent one step at a time.

5. Report done

Open an issue on your setup repository with the title Setup complete, assigned to larnsce, saying which of the steps 4 to 9 worked and which did not. You can have the agent do it. Start claude again in the terminal and ask:

Open an issue on this repository titled “Setup complete”, assign it to larnsce, and write in the body which of the pre-work steps 4 to 9 worked for me and which did not.

It uses the from step 5 for that. Allow the prompt if one appears, and check on GitHub that the issue exists. Opening the issue by hand, as you did in step 1, is just as good.

ImportantIf anything failed

Open the issue anyway, describe what failed and at which step, and assign it to me. A problem found now is half an hour of work. The same problem found on the morning of the workshop costs you the session.

Thank you for working through all of this. See you at Villa Hatt, ETH Zurich.
