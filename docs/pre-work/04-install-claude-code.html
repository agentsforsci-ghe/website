Step 4: Install Claude Code and log in

Due by Friday, 25 September 2026

Claude Code is the coding agent we use on the day. It runs in a terminal, works inside the folder you start it in, reads and edits files there, and runs commands. It asks before it runs a command or changes a file, and that permission prompt is the first thing to learn to read.

This step has four parts: get an account, install the program, log in once from a small repository I prepared for you, and put the Claude app on your phone for the day.

Part 1: Your Claude account

Claude Code is not part of the free Claude plan. You need one of the two routes below.

  • GHE members
  • Everyone else

You will receive an email invitation to the Global Health Engineering organization on the Claude Team plan, sent to your ETH email address. Accept it. If you do not have a Claude account under that address yet, the invitation walks you through creating one.

Use your ETH address, not a personal one. If you already use Claude with a personal address, the Team seat is a separate account and you log into Claude Code with the ETH one.

The invitation expires after three weeks. If none has arrived by the time you reach this step, tell me in the chat room.

On the Team plan, what you type and what the agent reads is not used to train models, and the group, not the vendor, controls the data. That is the reason for the plan.

Create your own account at claude.ai and subscribe to a paid plan for the month of the workshop. The Pro plan is enough. I suggest the Max plan for one month, since the day involves a lot of agent work and the Pro limits can run out in an afternoon. Cancel afterwards if you do not want to keep it.

Then do one thing before anything else: open your privacy settings and turn off the setting that allows your chats and coding sessions to be used for model training. On the Free, Pro and Max plans that setting is on unless you turn it off, and it covers Claude Code sessions. With the setting off, your data is kept for 30 days instead of five years and is not used for training.

Part 2: Install

The installer needs nothing else on your computer. Open a terminal and paste one line.

  • macOS
  • Windows

Open Terminal (in Applications, Utilities, or search for it with Spotlight) and run:

curl -fsSL https://claude.ai/install.sh | bash

Open PowerShell (search for it in the Start menu) and run:

irm https://claude.ai/install.ps1 | iex

Claude Code uses Git for Windows, which you installed for the first workshop, to run commands. If you skipped that step then, install it from git-scm.com first.

Close the terminal and open a new one, so it picks up the new program. Then check the install:

claude --version
claude doctor

The first prints a version number. The second checks the installation and prints what it found. Both should finish without an error.

TipWhich terminal

For the two install lines any terminal works. For working with Claude Code, give it a terminal window of its own next to your editor, not the Terminal tab inside RStudio, which is slow and cramped; Part 3 shows the layout. On the Mac, iTerm is a good alternative to the built-in Terminal; if you are interested in using it, get in touch. On Windows, run the two install lines above in PowerShell, and use whichever terminal you like afterwards.

Part 3: Clone your setup repository and log in

Clone your setup repository

I have created a repository for you in the organization, named setup-USERNAME with your GitHub username in place of USERNAME. It holds a small public dataset and one R script, and it is where every test before the day runs.

  1. Open the organization page, https://github.com/agentsforsci-ghe/, and find setup-USERNAME in the list of repositories. Use the search field on that page if the list is long.
  2. Open it, click the green Code button, and copy the HTTPS URL.
  3. In RStudio, choose File, New Project, Version Control, Git, paste the URL, and under Create project as subdirectory of browse to Documents/gitrepos/gh-org-agentsforsci-ghe, creating that folder if it does not exist yet. Then click Create Project. This is the same clone you did in the first workshop; the instructions from then still apply, screenshots included.

RStudio opens the new project. The Files pane at the bottom right shows 01-read-data.R, a data folder, and a README.

NoteWhere repositories live

The folder structure from the first workshop carries on. Every Git repository lives under Documents/gitrepos, in one folder per GitHub organization named gh-org- plus the organization, and one folder per personal account named gh- plus the username. So this workshop’s repositories go into gh-org-agentsforsci-ghe, next to the gh-org-gitforsci-ghe folder from July, and a personal website cloned from your own account would go into gh-rainbow-train, with your username in place of rainbow-train. Keep gitrepos out of folders that sync to a cloud drive.

ImportantNo repository with your name

Tell me in the chat room. Creating it takes me a minute.

Open a terminal at that folder

Claude Code works in the folder you start it from, so the terminal has to be opened inside the setup repository. Give it a terminal window of its own and put it next to RStudio: the two windows side by side, filling the screen, the editor on one side and the agent on the other. That is the layout for the whole day. RStudio and other editors have a terminal built in, and it does work, but it is slow and cramped for an agent, so keep it as a fallback.

  • macOS Finder
  • Windows Explorer
  • RStudio, as a fallback

Open Finder and go to the folder you just created, Documents/gitrepos/gh-org-agentsforsci-ghe/setup-USERNAME. Right-click the folder and choose New Terminal at Folder. A Terminal window opens inside it. If the entry is missing from the menu, look under Services in the same menu, or switch it on once under System Settings, Keyboard, Keyboard Shortcuts, Services, Files and Folders.

Open File Explorer and open the folder you just created. Right-click an empty area inside the folder and choose Open in Terminal. On Windows 10, hold Shift while right-clicking and choose Open PowerShell window here. Open Git Bash here, which Git for Windows added to the same menu, works as well.

With the project open, choose Tools, Terminal, New Terminal. A Terminal tab appears next to the Console, already inside the project folder. It works on both systems, and it is the slow, cramped option: use it only when the other two fail.

Whichever way you chose, the prompt in the terminal ends with the folder name, setup-USERNAME. If it does not, you are in the wrong folder. Now place the terminal window and the RStudio window side by side and make them fill the screen.

Log in

  1. In that terminal, start Claude Code:

    claude

  2. The first start asks you to pick a colour theme, then opens your browser to log in. Log in with the account from Part 1. If the browser does not open, press c to copy the login link and paste it into a browser yourself. GHE members: if asked which organization to use, pick Global Health Engineering.

  3. Back in the terminal, type /status and press Enter. It shows which account you are logged in with. Check that it is the one you intended.

  4. Look at the bottom line of the window, where Claude Code shows its permission mode. On the Team, Pro and Max plans it starts in auto mode: a built-in check approves ordinary actions on its own and asks you only when something looks risky. Pressing Shift+Tab switches to manual mode, where it asks before every command. Either is fine for the pre-work. On the workshop day we work in auto mode.

  5. Say hello. Type a greeting and press Enter. You get a greeting back. That is the whole test.

  6. Type /exit to leave.

Do not ask it to do anything else yet. Step 9 is where you give it work, with the safety rails in place.

NoteWhy a setup repository and not your own

The agent reads whole folders and sends what it finds to a model. Before the day, it does not see the data you committed in step 1. Every test in steps 4 to 9 runs in setup-USERNAME, which holds public data prepared for exactly this. We set the safety rails for your own repository together in the room.

Part 4: The Claude app on your phone

Install the Claude app on your phone for the day. You can delete it again afterwards. We use it once, to see how work started on the laptop carries on from the phone: a session running in the terminal is handed to the app, and from there you read what the agent did, send it the next instruction, and approve what it asks, while the laptop keeps doing the work.

  1. Install the app: App Store on an iPhone, Google Play on Android. If you have Claude Code open, typing /mobile shows a QR code that opens the right store.
  2. Sign in with the same account as in Part 1. GHE members use the ETH address and pick the Global Health Engineering organization if asked.
  3. That is all before the day. In the workshop, /remote-control in a running session shows a QR code that the app scans, and the session appears on the phone.
NoteThe Claude desktop app

There is also a Claude desktop app for the Mac and for Windows. Its Code tab is Claude Code with a graphical interface: a file pane, a diff view, a terminal built in, no command line needed. We do not use it in the workshop, so that everyone has the same thing on screen and reads the same prompts. It is an option afterwards for anyone who would rather work with the agent outside a terminal. It needs the same paid plan as Part 1 and brings its own copy of Claude Code, so Part 2 is not required for it.

ImportantIf the login fails on the ETH network

Claude Code needs to reach a handful of addresses (claude.ai, api.anthropic.com, platform.claude.com and downloads.claude.ai). If the login page never opens or the terminal reports a connection error while you are on eduroam or the ETH network, try again on a phone hotspot and tell me in the chat room which network failed.

NoteIf the install fails

Claude Code also exists as a website, claude.ai/code, that works from your GitHub repository without anything on your laptop. It is the fallback for the day if the local install cannot be fixed. Tell me before the workshop so we can set it up together.
