Agents for Scientists

Pre-course work

Thank you for joining this workshop. Your course instructor Lars Schöbitz is looking forward to meeting you.

We will meet on Tuesday, 29 September 2026 - 08:30 to 17:00 (Europe/Zurich) at Villa Hatt, ETH Zurich.

This is the second of the two workshops in the series. The first, Git for Scientists, ran on 15 July 2026 and is the foundation this day builds on.

Background

In the first workshop you learned to use Git and GitHub so that every change to a project is versioned, documented, and open to review. This workshop puts a coding agent inside that same workflow.

The day runs the real work of publishing a paper (analysing data, making interpretations, writing documentation) under three conditions: as you do it now without agents, with an agent given minimal input, and with an agent given a proper plan. Comparing the three shows what the agent actually does for you, what it does badly, and what is left for you to do.

Because the work runs through Git and GitHub, every action an agent takes and every decision you make is recorded as you go. That record is what makes agent use traceable and declarable, which is the second half of the day: research integrity bodies are writing the disclosure rules right now, and this group will send them a response written from what we do in the room.

Prior knowledge

This workshop assumes the Git for Scientists foundation. You should be able to:

  • clone a repository and open it as a project
  • run the pull, stage, commit, push cycle
  • create a branch and open a pull request
  • review a colleague’s pull request and merge it
  • open an issue, assign it, and close it

If any of these are shaky, work through the Git for Scientists material again before the day. You do not need any prior experience with AI coding agents.

What do I need to bring?

  • a laptop, connected to wifi, with your setup tested (Step 4 and Step 5 below)
  • a web browser
  • a pen and paper
  • a piece of your own data that can be shared openly (Step 1 below)
  • your notes and questions from the reading (Step 3 below)

What do I need to prepare?

There is pre-work for this workshop. It matters more than usual here: the day is built around your data and your questions, so a participant who arrives without them cannot take part in the main exercise.

Work through the six steps in order.

  • Step 1: Bring a piece of your own data
  • Step 2: Write down how you publish a paper
  • Step 3: Read the AI declaration questionnaires, by Friday, 26 September 2026
  • Step 4: Install Claude Code
  • Step 5: Test your setup, by Monday, 22 September 2026
  • Step 6: Complete the pre-course survey, by Monday, 15 September 2026

If you would rather read before you do, the four background pages cover the security, literacy, transparency, and disclosure themes the day works through. They are optional.

Learning objectives

By the end of this workshop, participants will be able to:

  1. Run an agent inside the Git workflow: give a coding agent a task, review what it produced as a pull request, and accept or reject the change.

  2. Judge the difference a plan makes: compare the output of an agent given minimal input against one given a reviewed plan, and say what changed and why.

  3. Judge the difference documentation makes: compare what an agent does with a plain CSV against the same data published as a data package.

  4. Locate your own practice: place your current way of working on the Reproducibility Levels framework, and name the next step from where you are.

  5. Declare agent use: point to the record your workflow produced and say what it shows about which parts of the work an agent touched.

What this workshop contributes

Research integrity bodies (WCRI, ISC, COPE, STM, and the Global Young Academy) are consulting on a global standard for reporting AI use in research. Round 2 of that consultation closes on 16 October 2026, which is after this workshop.

We will spend the last block writing a combined response from what we did during the day. Global Health Engineering will archive it with a DOI and submit it. Your pre-work reading in Step 3 is what makes that block possible, and your name goes on the result.
